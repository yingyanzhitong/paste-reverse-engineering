# 核心验证

在 `replica/` 目录执行：

```sh
swift build
swift run paste-replica-core-tests
swift build -c release
```

验证程序使用 Foundation、AppKit 和自定义断言，输出含 `passed`、`test_count`、`failure_count` 及逐组耗时的 JSON；失败时退出码为 1。当前只有 Command Line Tools 的环境缺少 XCTest，因此核心验证入口是 `paste-replica-core-tests`，不是 `swift test`。

所有用例创建独立临时目录与具名私有 NSPasteboard，结束后清理；不读写系统通用剪贴板，不读取原版数据库或用户历史，不运行原版。双进程用例会启动当前验证程序的两个 `--worker` 子进程，各自写入 30 条合成记录。

| 验证组 | 实际检查 |
| --- | --- |
| Unicode、搜索和去重 | 中文、组合重音、emoji；大小写和重音不敏感搜索；相同原始表示去重，不同 HTML 表示保留为独立项目；重开恢复及文件 0600 权限 |
| 分组、编辑和删除 | 同项目加入两个分组、移除指定分组、改名、删除分组保留内容；编辑清除陈旧 RTF；软删除、恢复、永久删除；无效分组错误 |
| 历史容量 | 超限时淘汰旧历史；已固定项目继续保留在分组并移出历史 |
| 陈旧实例合并 | 两个 Store 交错写入、偏好不同字段合并、同项目标题与分组修改保留；永久删除不被陈旧编辑复活 |
| 存档和损坏保护 | 导出、导入、重复导入幂等、保留本地不同项目、原始二进制及删除状态；拒绝截断存档，损坏数据库不被空数据覆盖 |
| 富文本和循环 | 真实 NSAttributedString 生成 RTF，保留 RTF/HTML 原字节；普通写回、纯文本写回；监控手动 poll 不重新采集自身写回 |
| 富文本编辑重开 | 替换陈旧表示并生成真实 RTF；重开后验证粗体、字号、颜色、下划线、段落对齐与 Unicode 正文，保留标题/来源/分组；私有剪贴板写回 |
| 只有 RTF 的内容 | 无独立文本表示时提取 Unicode 文本，同时保留原始 RTF 字节 |
| 多文件 URL | 两个独立 pasteboard item、中文/emoji/空格路径；保存重载后仍逐项保留原始 file URL 数据 |
| 大图和未知表示 | 生成真实 1024×1024 随机 PNG（大于 3 MB），重载、写回后逐字节相等且能被 NSImage 解码；未知二进制表示保留；无文本图片拒绝纯文本模式 |
| 采集策略 | Concealed、Transient、AutoGenerated 类型；来源排除；永久暂停、未来暂停截止、已过期暂停恢复 |
| 历史时间保留 | 0 天永久；过期未固定项目清理，过期固定项目保留但移出历史；截止内项目和未来时钟项目保留；旧偏好解码默认及并发偏好合并 |
| 闲置刷新和待保存编辑 | 反复无变化 reload/save 的 Combine 发布数为 0，数据库 inode 和修改时间不变；刷新合并远端变更并保留尚未保存的本地字段 |
| 独立进程写入 | 两个真正独立进程并发持久化 60 条不同内容，再由新实例检查无丢失及内容完整 |

## 存储和性能边界

0.3.0 核心增加多选原始表示顺序、分组重排/副本/清理、真实图片离线 OCR、瞬时类型开关仍防自身循环、清空历史保留固定项及 Stack 偏好重开/并发合并，共 19 组。

`test-ui-interaction.sh` 通过隐藏面板真实事件路由验证选择/拷贝/取消、快速粘贴与纯文本修饰键、分组跳转、Stack 反转持久化及队首消费、五档暂停和恢复。`test-window-policy.sh` 验证既有及新窗口的共享策略状态；`test-shortcut-model.sh` 验证旧配置解码、显式清除、录制校验与事件匹配。完整入口 `validate.sh` 已纳入这些检查。

CUA 合成数据演示验证搜索空状态、通用设置入口和实际 Option+Command+K 录制持久化。辅助进程已编译、嵌套打包并验证签名，尚未注册系统服务或做崩溃重启实验。旧版本空状态像素差异数据不作为新版测量结果。

数据采用 JSON 存储原始表示，跨进程通过独立锁文件 `flock` 串行写入。写入先生成权限 0600 的同目录临时文件、同步文件、原子 rename，再同步父目录。刷新以 inode、文件大小和修改时间判断磁盘是否改变；无变化时避免重新解码、发布和序列化。刷新保留尚未保存的本地修改，并以磁盘版本作为后续合并基线。历史时间和容量策略在保存事务中清理。

新内容或实际编辑仍会同步序列化整个 JSON；多 GB 历史、长期持续写入的性能，以及断电/文件系统故障恢复尚未经过压力测试。并发测试验证本实现遵守锁协议的独立进程，不能证明外部程序绕过锁直接改写数据时仍可无损恢复。

## 验收范围

0.3.1 的 `test-helper-lifecycle.py` 使用两个临时应用标识替换辅助进程源码中的常量，运行真实 AppKit 进程及 NSWorkspace KVO。它先验证未标记时不启动，再验证三秒延迟启动、不重复拉起、真实 SIGKILL 后产生新 PID、正常退出后不重启。首次测试确实暴露了终止通知方案的恢复失败，修改观察方式后回归通过。系统服务注册和启动错误分支仍不在此测试范围。

核心用例通过说明这些合成场景中的行为与数据完整性符合实现契约。它们没有证明与 Paste 6.6.6 的全部业务行为一比一等价，也不替代原版与复刻的受控对照。UI、全局快捷键冲突、辅助功能权限下直接粘贴、登录启动、系统声音、真实计时器长期运行、文件 promise、HTML 外部资源、云同步、账号和移动设备互通，需要各自独立验收。原始 representation 被保留不等于所有接收应用的粘贴行为均已验证。
